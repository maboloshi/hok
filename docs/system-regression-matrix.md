# Hok 系统级回归矩阵

> 目标：先进行系统级回归验证，TODO 差距项暂缓。

## 1. 覆盖维度

| 维度 | 子维度 | 覆盖目标 |
|---|---|---|
| 平台 | Windows x64 / x86 / ARM64 | 对齐 CI 目标（`.github/workflows/cicd.yml`） |
| 安装范围 | user / global (`-g`) | 路径、权限、行为一致 |
| 交互模式 | 交互 / `-y` 非交互 | 提示、确认、候选选择分支全覆盖 |
| 网络模式 | 在线 / `--offline` / `--ignore-cache` | 缓存命中、断网、强制下载路径正确 |
| 批处理鲁棒性 | 单包 / 多包 / `ignore_failures` | 失败隔离、继续执行、结果汇总正确 |
| 数据源 | 官方 bucket / 多 bucket / fixture | 兼容不同 manifest 形态与冲突场景 |
| 状态流转 | install → update/upgrade → reinstall/reset → uninstall/cleanup | 全生命周期状态一致性 |
| 输出与本地化 | `output-style` / `--no-color` / `--lang` | 文案、格式、可读性稳定 |

## 2. 优先级分层（P0 / P1 / P2）

- **P0（阻塞发布）**：核心交易链路、仓库与索引
- **P1（高优先级）**：查询可观测、清单质量工具、配置可移植性
- **P2（次优先级）**：外部集成能力

## 4. 通用检查项（每个测试点都执行）

1. **功能正确性**：退出码、输出、文件系统状态符合预期。  
2. **幂等性**：重复执行不破坏状态、不引入重复副作用。  
3. **可恢复性**：中断或失败后可重试恢复。  
4. **兼容性**：不与 Scoop 既有行为假设冲突（基于 fixture/兼容策略）。  

## 5. 执行规则

1. 按优先级执行：P0 → P1 → P2。  
2. 每个测试点记录：环境、输入、输出摘要、证据路径、结果。  
3. 若出现阻塞缺陷（数据破坏、无法恢复、跨架构阻塞），立即停止后续同域执行并提缺陷单。  
4. 所有失败项需可复现，并附最小复现步骤。  

## 6. 退出准则（回归通过定义）

- P0 **全部通过**
- P1 通过率 **≥ 95%**（剩余失败项必须有缺陷单）
- 无数据破坏类问题（包目录、shim、shortcut、config）
- x64 / x86 / ARM64 三架构无阻塞失败

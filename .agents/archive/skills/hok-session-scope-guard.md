用户 2026-09-12 明确要求：**一条会话跑偏了要"强提醒"另开对话。** 原话方向：
「后面的主题已经远远偏离最初的话题，未来请强提醒我新开对话处理」。

## 触发条件（同时满足才提醒）

1. 当前正在做的事**已经属于另一个独立主题**（不是开场问题的延伸实现细节）；
2. 该主题**还会继续展开**（有后续步骤、开放项、多轮改动），而不是"顺手一行修掉"。

典型样本（2026-09-12）：开场是「list/info 等表格输出是否抽公用模板」，
中途由 `hok info uv` 一个版本显示异常，演变成**清单缓存架构专项**
（marker 基线 `7b1effe`、按桶重建 `8a34463`、刷新转圈 `9613c13`）——
这类就该在发现根因是"缓存"而非"表格"时立刻提示另开对话。

## 做法

- **醒目提示**：在回复里用显式标题/引用块写出「⏩ 这已经偏离开场主题，建议另开对话」，
  不要埋在段落中间。
- **给出新会话范围**：建议标题 + 要处理的具体事项（例：
  `hok 清单缓存：命中即校验 / 本地桶 mtime 增量 / update 非 TTY 失败可见性`）。
- **确认前不把新主题做大**：先收尾当前这条线的提交与文档，然后停下等用户拍板；
  不要"边提醒边继续实现"。
- **已经产生的改动**：正常收尾（跑测试、提交、新建一条 devlog 条目（`.agents/docs/devlog/`）），**不要**因为跑偏就擅自回退；
  把"是否保留/回退"作为确认项之一交给用户。

## 与相邻规则的关系

- [[hok-investigate-first]]：管「动手前的确认门」；本 skill 管「**范围/会话卫生**」——
  它决定"要不要在同一条会话里做"，前者决定"动手前要不要报告"。
- [[no-patchwork-fixes]]：跑偏时容易顺手打补丁收场；提醒另开对话也顺带避免"为了接话而补"。
- [[hok-proactive-review]]：提交前的 review 门；review 时若发现后续工作属于新主题，
  同样应触发本 skill 的提醒。

要求今后**强提醒**。同日已同步记入 Hindsight 记忆（`hok`）。

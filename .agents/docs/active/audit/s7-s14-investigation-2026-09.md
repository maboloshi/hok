## 4. 共享文件与测试影响面（并行切分的约束）

**共享且必须成对修改的文件**：
- `locales/en.yml` / `locales/zh.yml` —— 两个命名空间：
  - `cmd:`（行 ~79–418）扁平结构，键按命令**前缀**散布（`list_*`、`status_*`、`bucket_*`、`shim_*`、`cache_*`、`cleanup_*`），不是按命令连续分块；
  - `cli_help:`（行 ~465–881）按**命令**分子树（`cli_help.bucket`、`cli_help.shim`、…）。
  - ⇒ 不同命令的改动落在不同区域，git 三方合并**多数可自动合并**；同命令内多键改动才可能冲突。
- 新增/重命名 clap 参数（如 `status -l`、`--skip-hash-check` 主名、`shim -g` 位置）**必须**同步 `cli_help.<cmd>.*` 的两个语种，否则 `tests/cli_help_i18n.rs` 报 raw key。

**锁定行为的测试**：
- `tests/exit_codes.rs` —— 锁 `bare hok` 0、未知命令 1、缺参 1、`which` 2、`bucket list` 2、`shim rm|info` 3、`virustotal` 8、`list` 空 1、`search` 无匹配 1、`status` 0、`uninstall|update ghost` 0。**任何退出码/参数改动都要重跑并可能改这个文件。**
- `tests/i18n_keys.rs` —— en/zh 叶子键集合必须完全一致；源码中每个 `t!("…")` 必须两语种都存在。**新增文案必须同时改两个 yml。**
- `tests/cli_help_i18n.rs` —— 遍历真实命令树渲染每个帮助：不得出现 raw `cli_help.` 键；中文短帮助里每个参数描述必须含 CJK。**它不比对 help 快照文本**，所以帮助文案改动是安全的；但新增参数必须补 i18n。

**跨命令单入口（no-patchwork-fixes 关键点）**：
- `src/cmd/mod.rs:62` 的 `status_info_word(InfoKind)` 是 `status` 与 `list` **共用**的 Info 词渲染入口。官方两处用词不同（`list`: `Deprecated package` / `Global install` / `Install failed` / `Held package`；`status`: `Deprecated` / `Install failed` / `Held package` / `Manifest removed`）⇒ 要改就必须**给该函数加语境的正确入口**（例如区分 `status`/`list` 的枚举参数），不能在各命令里各写一套。
  ⇒ **`status` 与 `list` 必须放同一个 workstream**（否则同一函数被两条分支改，必冲突）。

## 5. 并行切分方案

| 方案 | 切法 | 优点 | 代价 |
|---|---|---|---|
| **P1（推荐）** | 3 个 worktree：**A** = `status`+`list`+`search`（含 `cmd/mod.rs` 单入口）；**B** = `bucket`+`shim`；**C** = `install`/`update`/`upgrade`/`download`/`cache`/`cleanup` 文案 + `reset` 退出码 | 文件级基本不重叠（仅 `locales/*` 与少量 `cli_help.*`）；与用户「并行开发」一致 | 3 条分支都要 rebase 到最新 tip；`locales/*` 冲突需手工保双方语义 |

`pwsh "$HOME/.agents/skills/worktree-parallel/scripts/worktree-merge.ps1" -Worktree .worktrees/<...> [-VerifiedRef <实测 ref>]`。

# S3 调研报告：`export` / `import` 与官方 Scoopfile 互通（2026-09-12）

> 会话来源：`.agents/docs/active/plan/command-deviation-fix-plan-2026-09.md` §S3（报告 §6.4，10 条）。
> worktree：`.worktrees/s3-export-import`，分支 `fix/export-import-interop`（基于 `3d4969f`）。
> 本报告只做调研与选项，**未改任何代码**；等确认后再动手。

---

## 1. 结论摘要

1. **两个方向都不通**：hok 的 `export` 输出官方不认；官方的 Scoopfile hok `import` **静默空跑**（实测 exit 0 + 一条 warn，什么都不做）。
2. 根因不是细节偏差，而是**两套 schema 完全不同**（hok＝`{buckets:{名:url}, apps:{bucket:{名:版本}}}`；官方＝两个**对象数组**，元素含 `Name/Version/Source/Updated/Info`）。
3. 本次实测还发现报告 §6.4 **未登记的两处缺失**：
   - `export` **不含全局安装的 app**（`apps_dir()` 走 `effective_root_path()`，只扫一个作用域）；
   - `export` 用的 `-a` 语义官方没有（官方无条件导出全部，含 URL/本地清单安装）。
4. 建议方案 **A′：`export` 采官方 schema + `import` 双格式读（官方数组 + hok 旧对象）**；`-c/--config` 建议**暂缓或降到 S4**（hok 的配置键名与官方有 6+ 处不一致，且官方独有键 hok 严格拒绝）。
5. **附加调查（§9）发现一个更前置的阻断项**：`hok export > file` 的产物被 `ESC[?25h`（退出时无条件恢复光标，`src/bin/hok.rs:9`）污染，`hok import file` **连自己的产物都读不了**（`trailing characters`，exit 1）；官方 `ConvertFrom-Json` 同样在解析阶段就失败。修 schema 之前必须先修这一条。

## 2. 现象与复现（实测）

环境：`target/release/hok.exe`（3d4969f 构建），`SCOOP=D:\App\Scoop`，已装 100+ 包。

**2.1 官方 Scoopfile 导不进 hok（核心复现）**

构造一份按官方 `scoop-export.ps1` 语义生成的 Scoopfile（`buckets` 数组 + `apps` 对象数组），执行：

```
hok import %TEMP%\s3-official-scoopfile.json
→ WARN 导入文件中没有找到包。
→ [exit=0]
```

即：**成功退出、什么都不装**。代码路径：`import.rs:36-37` 用 `Value::as_object()` 取 `apps`/`buckets`，官方两者都是**数组** → 全部 `None` → `packages` 为空 → `src/cmd/import.rs:35-38` 走 "no pkgs" 分支 `return Ok(())`。

**2.2 hok 现有输出（实测 `hok export` 头部）**

```json
{
  "buckets": { "extras": "https://github.com/ScoopInstaller/Extras", "main": "https://github.com/ScoopInstaller/Main", ... },
  "apps": { "main": { "7zip": "26.03", "aria2": "1.37.0-1", ... }, "scoop-app": { ... } }
}
```

官方 `scoop export` 的形状（源码语义，见 §4.1）：

```json
{
  "buckets": [ { "Name": "main", "Source": "https://github.com/ScoopInstaller/Main", "Updated": "2026-09-01T10:00:00+08:00", "Manifests": 1300 } ],
  "apps": [ { "Name": "7zip", "Version": "26.03", "Source": "main", "Updated": "2026-09-02T10:00:00+08:00", "Info": "" } ]
}
```

## 4. 双方 schema 精确定义（实现依据）

### 4.1 官方（唯一权威：源码路径）

- `buckets` ← `list_buckets`（`lib/buckets.ps1:104-121`），用户级 bucket（无全局 bucket 概念）：
  `Name`；`Source`＝git remote.origin.url，非 git 时 `friendly_path $path`；`Updated`＝git 最后提交日期，非 git 时 `<path>\bucket` 目录 mtime；`Manifests`＝`bucket/` 下文件数。
- `apps` ← `scoop-list.ps1`（`libexec/scoop-list.ps1:29-61`）本地+全局合并，元素：
  `Name`；`Version`＝`Select-CurrentVersion`；
  `Source`＝`install.json.bucket` → bucket 名；否则 `install.json.url`，且 **url == `usermanifest $app` 时记作 `<auto-generated>`**；否则该 url 原样；
  `Updated`＝app 目录 mtime，有 `install.json` 时取该文件 mtime；
  `Info`＝`', '` 连接的状态串，**顺序固定**：`Deprecated package`、`Global install`、`Install failed`、`Held package`、架构（仅当 ≠ 默认架构）。无内容时为**空字符串**。
- `config`（仅 `-c`）：`$scoopConfig` 去掉 `last_update/root_path/global_path/cache_path/alias`。
- `scoop-export.ps1` 输出 `ConvertToPrettyJSON` 到 stdout；`scoop import <file|url>` 用 `parse_json`/`url_manifest`（URL/UNC）。

### 4.2 hok 现状

- `export`：`buckets`＝`bucket::list()` 中有 `remote_url()` 的（名→url）；`apps`＝`query("*", installed=true)` 按 `installed_bucket()` 分组（名→`installed_version()`），isolated 归 `__isolated__`（`constant.rs:31`）且默认跳过。
- `import`：只认 `apps`/`buckets` **对象**（`apps` 优先，其次旧格式 `buckets`）；返回 `Vec<"bucket/name">`；随后一次 `sync`。

### 4.3 hok 侧数据是否齐备（做官方 schema 的可行性）

| 官方字段 | hok 可用来源 | 状态 |
|---|---|---|
| app `Name` / `Version` | `Package::name()` / `installed_version()` | ✅ |
| app `Source`（bucket 名） | `installed_bucket()` | ✅ |
| app `Source`（URL/路径） | `install.json.url`（`InstallInfo::url()`）；isolated 安装写的就是清单 URL／本地绝对路径（`manifest_source.rs:47-67`）或 workspace 用户清单（`generate_user_manifest`，`session.workspace_dir()`＝`<root>/workspace`） | ✅ 可判定 `<auto-generated>` |
| app `Updated` | app 目录／`install.json` mtime（需格式化，当前只有 `internal::time::format_short_local` 日期级） | ⚠ 需补格式化 |
| app `Info` | `Package::is_install_failed()`、架构＝`installed_arch()`＋默认架构、held＝`Package::is_held()`、deprecated＝`package::status`/`info.rs:220-235` 的检测 | ✅ |
| bucket `Source`/`Updated`/`Manifests` | `Bucket::remote_url()`／`updated_at()`（git HEAD 日期，非 git 时 `None`）／`manifest_count()`、`Bucket::source()`（本地路径） | ⚠ 非 git bucket 的 Updated 需回退到 `bucket` 目录 mtime |
| `config` | `Config` 序列化 + 剔除键 | ⚠ 键名/白名单问题（见 §6 决策点 3） |

## 5. 候选方案与代价

| 方案 | 内容 | 代价/风险 | 互通性 |
|---|---|---|---|
| **不改** | 维持现状（两套格式各自自洽） | 0 | ❌ 双向都不通 |
| **B 仅 import 兼容** | `import` 认官方数组 + hok 旧对象；`export` 不动 | 小（改 1 个解析模块 + cmd 映射）；`hok export` 的产物仍无法被 Scoop 使用 | 单向（Scoop→hok） |
| **A 全面采纳官方 schema** | `export` 直接输出官方字段；`import` 只认官方格式 | 中；**破坏 hok 旧 Scoopfile**（老用户存的 hok 格式导不回） | ✅ 双向 |
| **A′ 官方 schema + import 双格式读**（推荐） | `export` 输出官方 schema（含全局 app、isolated、`-c`）；`import` 先按官方解析，失败/形状不符时回退 hok 旧对象格式 | 中（比 A 多一个兼容分支，约 30 行 + 测试）；旧格式仍可导回 | ✅ 双向 |
| **C `--format scoop\|hok` 双输出** | `export` 加格式开关，默认官方 | 中+（多一个公开开关，长期要维护两套输出）；用户脚本要显式传参 | ✅ 双向 |

**推荐 A′**：interop 是本条会话的唯一价值，`-a`/旧格式都不值得保留成两套输出；旧格式只作为 **import 的读兼容**保留（成本低、不产生第二套 export 代码路径），符合 `no-patchwork-fixes`（不给 export 加开关掩盖两套语义）。

## 9. 实测对照：两边"导入数据"逐项差异（2026-09-12，附加调查）

同一台机器（`SCOOP=D:\App\Scoop`，72 个 app 目录）上用两条链路生成"导入数据"再对照：

- 官方侧：`.worktrees/s3-export-import/.tmp/synth-official-export.ps1`，逐行复演 `libexec/scoop-export.ps1` + `libexec/scoop-list.ps1:29-61` + `lib/buckets.ps1:104-121`（脚本仅作证据，不入库）；
- hok 侧：`hok export`（release 3d4969f）；
- 对照：`.tmp/diff-inputs.js`；官方导入推导复演：`.tmp/replay-official-import.ps1`。

### 9.1 结构差异（字段级）

| 路径 | 官方 | hok | 差异 |
|---|---|---|---|
| `config` | 仅 `-c` 时存在 | 无 | 缺失 |
| `buckets` | **对象数组** | **对象 map** | 类型不同 |
| `buckets[].Name` | 字段 | map 的 key | 位置不同 |
| `buckets[].Source` | git remote.origin.url；非 git 用 `friendly_path`（本地路径） | map 的 value＝`remote_url()`，**非 git bucket 整条丢弃** | 覆盖/语义不同 |
| `buckets[].Updated` | 有（git 日期 / 目录 mtime） | 无 | 缺失 |
| `buckets[].Manifests` | 有（`bucket` 目录递归计数） | 无 | 缺失 |
| `apps` | **对象数组** | **对象 map（bucket → {名:版本}）** | 类型不同 |
| `apps[].Name` / `Version` | 字段 | 内层 key / value | 位置不同 |
| `apps[].Source` | bucket 名 ／ URL/本地路径 ／ `<auto-generated>` | 外层 key（bucket 名或 `__isolated__`） | 语义不同；isolated 默认**整类丢失** |
| `apps[].Updated` | 有（`install.json`/app 目录 mtime） | 无 | 缺失 |
| `apps[].Info` | `Deprecated package, Global install, Install failed, Held package, <arch>` | 无 | 全局/held/arch/失败信息全丢 |

### 9.2 同一安装的实测内容差异

- **apps：官方 72 条 vs hok 68 条**；hok 缺 4 条、多 0 条、版本不一致 0 条：
  - 缺的 4 条＝`Fiddler`（连版本目录都没有）、`potplayer`、`sublime-merge`、`sublime-text`（`current` 链接在，但 `install.json`/`manifest.json` 缺失）；
  - 官方把 4 条都导出，`Info='Install failed'`；hok `list` 也显示"安装失败"，但 **`export` 静默丢弃**（`query.rs:120-121` 要求 manifest+install 都可解析，export 未带 `Broken` 选项）。
- **buckets：4 vs 4，名称与 URL 完全一致**（本机无"非 git 本地 bucket"，故 Source 回退差异未暴露）。
- 典型同包对照：
  - `extras`：官方 `{"Name":"extras","Source":"https://github.com/ScoopInstaller/Extras","Updated":"2026-09-12T20:37:54.8603016+08:00","Manifests":2383}` ↔ hok `"extras":"https://github.com/ScoopInstaller/Extras"`；
  - `7zip`：官方 `{"Name":"7zip","Version":"26.03","Source":"main","Updated":"2026-09-04T20:06:02.386467+08:00","Info":""}` ↔ hok `apps.main["7zip"]="26.03"`；
  - 本机唯一非空 Info 的包 `dingtalk@7.0.10.1026`（held）：官方 `Info="Held package"` ↔ hok 只有版本号，**hold 状态丢失**。

### 9.3 反向：官方读 hok 的导出文件

1. **先卡在解析**：`hok export > hokfile.json` 的文件末尾带 `ESC[?25h`（见 9.4），官方 `parse_json`（`ConvertFrom-Json`）直接报
   `Conversion from JSON failed with error: Additional text encountered after finished reading JSON content` → 随后 `abort 'Input file not a valid JSON.'`
2. 剥掉该转义后按 `scoop-import.ps1` 逐行推导（实测复演）：`$import.buckets`/`$import.apps` 是 **PSCustomObject 而非数组** → foreach 只迭代一次，`Name/Source/Version/Info` 全为 `$null` → 实际动作＝`add_bucket '' ''`、`scoop-install.ps1 ''`（均失败）。
   对照（官方格式，同脚本）：正确推导出 `add_bucket extras …`、`scoop-install.ps1 'main/7zip'`、`'scoop-app/android-platform-tools'`。

### 9.4 新发现（阻断级，位于 schema 之前）：export 输出被 ANSI 转义污染

- 根因：`src/bin/hok.rs:9` 无条件 `std::io::stdout().execute(crossterm::cursor::Show)`（"退出前恢复光标"），stdout 被重定向时照样写入。
- 实测：
  - `hok export | Out-File x.json` → 文件尾部＝`\n}\r\n` + `ESC[?25h` + `\r\n`；
  - `hok import x.json`（**自己的产物**）→ `ERROR 解析 JSON 失败：trailing characters at line 2 column 1`，exit 1（用 `{"apps":{}}` + 该转义复现，避免真装包）。
- 结论：`hok export > file` + `hok import file` 的官方推荐用法**当前根本不成立**；修 schema 之前必须先修这一条（正确入口＝"仅在 stdout 是终端时才恢复光标"，`IsTerminal` 守卫，不加开关）。

### 9.5 导入端"消费能力"对照

| | 官方 `scoop import` | hok `import` |
|---|---|---|
| 输入 | 本地路径 / http(s) URL / UNC | 仅本地文件 |
| `config` | 逐键 `set_config` + 打印 | 完全忽略 |
| `buckets` | 逐条 `add_bucket Name Source` | 不处理（且被误当 bucket→apps 映射） |
| `apps` | `Name/Version/Source/Info` → 安装查询；`Info` → `--global`/`--arch`；装后 hold | 仅取外层 bucket 名 + app 名 → `bucket/name`；`apps`/`buckets` 必须是**对象** |
| 安装方式 | 逐 app 普通 install | 一次批量 `sync`（强制 `AssumeYes` + `IgnoreFailure`） |
| 失败/缺件 | 未安装的 app 也照样尝试；`Install failed` 信息不参与安装 | 缺 manifest/install.json 的 app 直接无法进入导入清单 |

### 9.6 对 S3 方案的影响

- 9.4 属**独立小修、但为前置**：建议单独一个提交（`src/bin/hok.rs` 一处守卫），否则 export/import 的往返在任何方案下都不可用；
- 9.2 的 4 条"安装失败"app 需要一条明确策略：官方（导出并标 `Install failed`）／hok 现状（静默丢弃）——建议导出但标注，导入时跳过并 warn（否则会把失败包当正常包重装）；
- 9.2 的 `dingtalk@7.0.10.1026`（`apps` 下带 `@版本` 的目录名）与 `Info` 丢失相关：该形态下 hold 信息只在 `install.json`，导出必须读 install.json 才能保住；同时该目录名本身疑似异常（另案，不在 S3 展开）。

## 10. 方案细化（依用户 2026-09-12 提议，待确认）

用户提议：**import 只导入兼容子集并报告未导入项与原因（导入 hok 自己的格式则全兼容）；export 分两种输出，用参数区分：仅 Scoop 兼容 / hok 自有**；并指出两边"数据格式当前一致"（内容字段相同，只是容器形状不同）。

**据此的实现取向（建议）**：不维护两套 schema，只维护**一种官方形状**，hok 模式＝官方形状 + 扩展段；`--format` 只控制是否输出扩展段/是否把 config 键名映射成官方名。

### 10.1 导入官方 Scoopfile 的"未导入/降级"清单（含原因，用于报告）

| Scoopfile 内容 | hok 处置 | 是否需报告 |
|---|---|---|
| `buckets[].Source`＝非 git（本地路径 `friendly_path`） | `bucket::add` 只支持 git URL → **跳过** | ✅ 原因：hok 不支持本地路径 bucket |
| `buckets[]` 已存在同名/同仓库 | 跳过（官方 `add_bucket` 也是 warn + 返回 2） | ✅ 警告 |
| `apps[].Info` 含 `Install failed` | 官方照装；hok 建议**跳过**（避免把失败包当正常包重装） | ✅ 原因：安装元数据缺失 |
| `apps[].Info` 含 `Global install` | 支持（需按 (global, arch) 分组切 `session.set_global`） | 不需要 |
| `apps[].Info` 架构 ≠ 默认 | 支持（分组切 `session.set_default_architecture`） | 不需要 |
| `apps[].Info` 含 `Held package` | 支持（装后 `package::hold`） | 不需要 |
| `apps[].Info` 含 `Deprecated package` | 不影响安装 | 可选提示 |
| `apps[].Source`＝URL / 本地路径 | 支持（isolated 安装，需下载/读清单） | 下载失败时 ✅ |
| `apps[].Source`＝`<auto-generated>` | 支持（`name@version` → autoupdate 生成用户清单） | 无 autoupdate 支持时 ✅ |
| `apps[].Version`（bucket app） | **与官方一致：不 pin 版本**，装 bucket 当前版本 | ✅ 需提示"版本字段仅对 `<auto-generated>` 生效" |
| `apps[].Updated` | 不参与安装 | 静默忽略 |
| `config` 官方独有键（`aria2-options`/`aria2-retry-wait`/`aria2-warning-enabled`/`autostash-on-conflict`/`debug`/`force-update`/`hold-update-until`/`manifest-revision`/`scoop-branch`/`scoop-repo`/`shim`/`show-manifest`/`show-update-log`/`update-nightly`/`use-external-7zip`/`use-lessmsi`/`use-innounp`） | **跳过**（hok `config.set` 严格拒绝） | ✅ 逐键原因 |
| `config` 键名不同形（`use-sqlite-cache`/`ignore-running-processes`/`last-update`/`gh-token`/`virustotal-api-key`/`default-architecture`/`use-isolated-path`/`no-junction`/`cat-style`/`cache-path`） | 映射为 hok 键名后写入 | ✅ "已映射为 hok 的 X" |
| `config` 含 `alias`/`root-path`/`global-path`/`cache-path` | 官方 export 已剔除；手改文件里若存在 → 跳过 | ✅ |

### 10.2 导出两模式

- **`--format scoop`（仅兼容）**：官方形状 + 官方键名的 `config`（hok 键映射到官方名，剔除 hok 专属键），保证官方 `scoop import` 可解析并正确还原（`Global install`/架构/`Held package` 全走 `Info`）。
- **`--format hok`（自有/无损）**：同一形状 **+ 扩展段**（如 `Hok: { config: <hok 原始 config> }`，及每个 app 的显式 `Hold`/`Architecture`/`Global`/`Failed` 字段），保证 hok→hok 无损（不依赖解析 `Info` 字符串）；官方读它也能装（多余键被忽略）。
- 两模式**共用同一序列化器**，差异只在一个字段白名单/键名映射函数（`no-patchwork-fixes`：不给两条独立代码路径）。
- 待定：默认模式（建议 `scoop`）、参数名（`--format` / `-f`）。

## 11. 最终决定与落地结果（2026-09-13 收尾）

用户拍板：① 单一 schema（官方形状 + 官方会忽略的扩展段）；② 扩展段开关用 **`--hok`**（不是 `--format`）；③ 未导入项的退出码**按 S1 收口**（S1 已在另一分支落地：逐项报错、批处理不失败、exit 0）；④ §6.3 其余默认（`Install failed` 跳过并报告、`-c/--config` 留待 S4、空 source 回落内建 bucket、ANSI 修复先提交）全部采纳。

落地（分支 `fix/export-import-interop` → 已线性 ff 进 `refactor/edition-2024`）：

| 提交 | 内容 |
|---|---|
| `a61a471` | `fix(cli)`：光标转义仅在终端（9.4 阻断项；含 eventloop 的 CursorGuard） |
| `110e160` | `feat(export)`：官方 Scoopfile 形状 + `--hok` 扩展（全局作用域、isolated、`Updated`、`Info`；删 `-a`） |
| `2dd84b2` | `feat(import)`：官方数组 + hok 旧 map 双形状；兼容子集 + 逐条报告；URL/UNC 输入；分组安装 + hold |
| `14b9c29` | `feat(export,import)`：别名随 `hok.aliases` 往返（`alias::body` 保行结构；`Hok`/`hok.config` 与官方忽略规则不变） |

与 §10 提案的差异（实现时收敛）：扩展段的每 app 字段**不含 `Url`**（`Source` 已完整表达，避免双权威）；`hok.config` 里剔除 `alias` 索引（改由 `hok.aliases` 承载命令，导入走 alias API）；条目按 (global, arch) 分组，无 arch 覆盖的组先跑（arch 覆盖是进程级、公开 API 无法回退）。

实测（`SCOOP=D:\App\Scoop`，72 个 app 目录）：

- `hok export` = 72 app / 4 bucket，与"官方导出逻辑复演脚本"逐条一致（`Info` 全等、版本 0 冲突）；差异仅 3 个 broken app 的 `Version`（hok `null` vs 官方 junction 目标名，两者都无法据其重装）；
- `hok export --hok` 额外带 `hok`（`config` + `aliases`）与 `Hok`；官方导入逻辑对它与纯官方文件推导出相同的安装参数；
- `hok export > f.json` 不再带 `ESC[?25h`；`hok import f.json` 自身往返可用（此前 `trailing characters` 直接失败）；
- 隔离 `SCOOP` 沙箱内往返：导出（含 held + 32bit + 别名正文）→ 导入 → 别名按 `alias add` 还原、应用计为已导入；官方 Scoopfile（72 条）导入：4 条 `Install failed` 跳过、其余尝试后按实际结果汇总。

已知限制（登记，不在本条范围）：`-c/--config`（官方键名导出）随 S4；别名"已存在"时报跳过（`alias add` 拒绝覆盖）；非 git 本地路径 bucket 只能报告跳过（hok `bucket add` 仅支持 git 远程）。

调查用脚本（`.worktrees/s3-export-import/.tmp/*.ps1|js`：官方导出复演、导入推导复演、superset 构造、locales hunk 拆分）为一次性产物，随 worktree 清理删除；其方法与命令见 §9.1 与本节，可按需重建。

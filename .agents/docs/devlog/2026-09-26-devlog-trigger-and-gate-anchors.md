**教训（三条）**：

1. **只有常驻层保证"该用的时候读得到"**：技能正文按需加载，闸门写在里面等于没有。闸门必须在根 `AGENTS.md`
   有锚点，锚点只写"时机 → 指向"，参数留在本体。
2. **复述必漂**：8 份复述漂成 3 种口径；同一条规则除本体外只允许**引用**，发现第二处复述就收敛。
3. **规则文字会与先例冲突**：`.agents/AGENTS.md` 写"日志与代码同提交"，但条目第 3 行要引用主题 sha、物理上
   无法自引——先例（`000d97f`）早就是"日志自成一条收尾提交"。**先 `git log <规则文件>` 再相信规则文字。**

**四、审计的两项处置（`d3d6ffb`）**：① 脚本区按"是否还要再跑一次"分流——两个 `.ps1` 探针只以 `.agents/tmp/`

→ 改为在根 `AGENTS.md` 明写"这些闸门由机器本地技能承载、缺该根则不生效"，并在 `.agents/skills/AGENTS.md`
立下"不得同名、补充用 `hok-*` 且只指向本体"的规则。

# 把「怎么写 skill」补进技能规范本体，并清掉两处会漂的指针

> 2026-10-03 ｜ 提交 `625c2a4` ｜ worktree 主树（`D:\App\github项目\Scoop\hok`）｜ 分支 `refactor/edition-2024`

## 背景

同一会话里先写了四份技能补充（并发纪律 / 门禁跑几次 / fmt 假绿 / 对标三类读取），随后按
[`.agents/skills/AGENTS.md`](../../skills/AGENTS.md) 的判据 review，发现两件事：

1. 现有规范只回答**「什么留在技能里」**（"把日期和提交号删掉还有指导价值吗"），不回答
   **「留下来之后长什么样」**，也不提**同一主题被两个技能各写一份**该怎么办；
2. 那次 review 修掉的矛盾（`hok-rust-gate-practice` 说"别传含 `mod` 的文件"、`hok-agent-orchestration`
   要求"整文件 `rustfmt --check`"）**正是第 2 点缺失的产物**：两处各写一半、方向相反，只看一处都合理。

## 改了什么（`625c2a4`）

规范本体 `.agents/skills/AGENTS.md` 新增两节：

- **写法**：默认形态 = 祈使句 + 一句"为什么" + 至多一句判例；判例只留"删掉史实后仍能复现的形态"
  （过程叙述、计数、会话编号一律不写）；日期只允许出现在"某时点已失效"的时间锚与规则的**制定日期**；
  单文件超 ~12 KB / ~120 行触发自查（退化信号是**只增不减**）；指针指路径或索引，**不指已归档文档的小节号、
  不指计划项编号**（豁免：索引表登记 `reports/**` 冻结文件名，按 R5 永不改名）。
- **一致性**：一处本体、别处指针。改技能前先 grep 其它技能文件是否也有同一主题的规则体；**违反的后果是
  「直接矛盾」而不是「文字漂移」**（两处都写完整规则时没人会同时看到它们）；改全局技能根时按同一纪律。

同时清掉上一轮 review 报的两处既有违反项：`hok-worktree-parallel` 的收尾说明里去掉已归档计划名 +
计划项编号 + 小节号，`hok-code-organization` 去掉指向审计报告的小节号（结论原文已就地写清）。

## 判据与遗留

- 没有把「一处本体」做成门禁脚本：是否同一主题需要语义判断，脚本只能给假绿；靠"改技能前 grep 一次"。
- 没有重写全部 16 个技能：只修已知违反项，其余等各自下次被改时按新规范收敛，避免又一次大爆炸 diff。
- 全量扫描技能目录，剩余 `§` 号与计划项编号命中均为合法（索引表指向冻结文件名、本仓文档标准 R 编号、
  新建规范里的反例本身）。
- 门禁：`doc-links.mjs` / `docs-index-check.mjs` / `devlog-index.mjs --check` 全部 exit 0；
  16 个技能的 frontmatter `name` 与文件名一致。

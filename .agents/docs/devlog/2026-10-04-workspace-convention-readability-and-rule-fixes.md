## 背景

`agent-workspace-conventions` 第一版把约定压得很紧、句中到处加粗，人类读着发晕。重排的目标是
**可读性上去、token 不上去**；顺带修掉 review 时发现的两处"规则与事实相反"。

## 改了什么

**全局技能**（机器本地，不入本仓）：`SKILL.md` 重排——`-` 与 `1.` 的混用统一成编号、每行只在规则名处
加粗、每节补一句导语、规则组之间留空行、表格单元格只放短语；`templates/docs-AGENTS.md` 与
`templates/workspace-AGENTS.md` 按同一套规则过了一遍。SKILL.md 字节 10094 → 10425（**+3%**），
行数 127 → 147。

**本仓两处规则**：

- `46be764`——根 `AGENTS.md` 说仓内技能副本"会被更高优先级的根压掉"，与 rank 表相反（项目 100/200 <
  用户 400/500，rank 小者胜 ⇒ 是仓内副本**压过**全局副本）。理由改成真正成立的那条：它只是第二处
  会漂的定义。
- `754a56b`——`.agents/skills/AGENTS.md` 的体量自查从"~12 KB **或 ~120 行**"改成"~12 KB（行数只作辅助）"。

## 教训

1. **行数是 token 的坏代理**：同一次重排里字节只动 3%，行数动了 16%。拿行数当体量闸门，会因为
   "为可读性加空行"而假报警，反过来逼人砍可读性。
2. **一条规则一个编号**：把多条规则塞进同一个 bullet、靠句中标点与加粗硬切，读者得逐字解析才分得出
   边界；拆开后每条只粗体化规则名，扫一眼就能定位。
3. **加粗是稀缺资源**：处处加粗等于没加粗。
4. **规则与事实相反时要按事实改**：rank 那句是改动前就有的旧措辞，但迁移后全局根也叫 `.agents/skills`，
   再留着的代价从"含糊"变成"读反"。

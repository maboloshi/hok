# S3：`export`/`import` 与官方 Scoopfile 互通

> 2026-09-13 ｜ 4 commit：`a61a471` `110e160` `2dd84b2` `14b9c29`

**背景**：`hok export` 输出自有 map 形状、`hok import` 只认该形状，官方 Scoopfile 导进来是"静默空跑 exit 0"。

- **先修阻断项**（`a61a471`）：`bin/hok.rs` 与 `eventloop.rs` 的 `CursorGuard` 在 stdout 被重定向时也写 `ESC[?25h`，导致 `hok export > f.json` 的产物尾部多一个转义 —— 官方 `ConvertFrom-Json` 报 `Additional text encountered`，hok 自己 `import` 报 `trailing characters`。改为只在 `stdout().is_terminal()` 时恢复光标。
- **一种 schema**（`110e160`）：`export` 直出官方数组形状（含本地+全局作用域、isolated、`Updated`、`Info`；时间戳用 `internal::time::format_last_update` 的 `.NET` round-trip 形状），`-a` 删除；`--hok` 另加顶层 `hok`（自身 config + 别名命令）与逐 app `Hok`（Hold/Global/Architecture/Failed），官方会忽略这两处，仍是合法 Scoopfile。
- **import 兼容子集 + 报告**（`2dd84b2`）：官方数组与 hok 旧 map 双形状；config → buckets → apps 顺序；本地/URL/UNC 输入；按 (global, arch) 分组安装并在装后 `hold`；跳过项逐条给原因（非 git/已存在 bucket、官方独有或机器相关 config 键、`Install failed` app、`<auto-generated>` 缺版本、来源 bucket 不可用）；退出码沿用 S1 口径 0，结尾按"实际已安装"汇总。
- **别名随扩展段往返**（`14b9c29`）：S2 后别名命令在 shim 脚本里，导出 config 会丢命令 ⇒ 新增 `alias::body`（保行结构）并由 `hok.aliases` 承载，导入走 `alias add` 重建脚本与索引。

## 验证

`cargo test --workspace` 609 passed / 2 failed —— 失败的是 `permission::tests::grant_users_write_inherit_*`（本沙箱禁止改 ACL，`error 5`，与本改动无关）。实测（`SCOOP=D:\App\Scoop`）：`hok export` 72 app / 4 bucket 与"官方导出逻辑复演脚本"逐条一致（`Info` 全等），差异仅 3 个 broken app 的 `Version`（hok `null`，官方记 junction 目标名，两者都不可据以重装）；`hok export --hok` 的扩展段被官方导入逻辑忽略且安装参数与纯官方文件相同；隔离 `SCOOP` 沙箱内 `export --hok → import` 往返：held/32bit/别名正文全部还原，应用计为已导入。`rustfmt --edition 2024` 合规 · `clippy` 本仓 0 warning。落地按 `hok-worktree-parallel` §5：rebase 到 `140d04a` 后线性 `--ff-only`（无 merge commit），`git diff --quiet <已验证 tip> HEAD` = 0。

## 教训

1. 机器可读输出（`export`）与终端控制序列必须在**写出点**就分流：判断属于"是不是终端"，不属于"调用方要不要颜色"。
2. 把"未导入"当报错会毁掉导入的可用性（一条坏记录让整批失败）；正确形态是逐条报原因 + 结尾汇总 + 批处理 exit 0（与 S1 的 download 一致）。
3. 反过来，"批处理成功"不等于"装上了"：`IgnoreFailure` 下必须回查实际已安装再计数，否则 broken app 会被统计成已导入。
4. 会话级开关（`--global`/`--arch`）要在导入侧显式**分组**，且进程级覆盖（arch）无法回退 ⇒ 无覆盖的组先跑，别指望"设回去"。

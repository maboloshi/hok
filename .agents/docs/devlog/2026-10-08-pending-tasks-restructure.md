## 教训

1. **清单腐烂的机制是"只进不出"**：状态词表不是关键，**出清口径**才是——做完只是六种去向之一，
   其余五种（被取代 / 合并升级 / 降级为想法 / 转长期登记 / 来源失效）同样要留一句理由与去向。
2. **重排必须配一次逐条核对**：第一版草案漏了 8 条开放项，其中一条（Wave 1 备份分支）已被现实改写
   （两个分支早就不存在，只剩一个）——只靠"看起来都在"会静默丢条目。
3. **引用会静默失效且没有门禁能查**：条目里的 `符号（file.rs:行）`，实测该符号已从 1234 漂到 1259；
   改指符号名与 stable ID 是唯一能自查的写法。
4. **删段落前先问"这段的独有事实在哪还有本体"**：本次两条环境坑全仓仅此一处；上一次技能拆分也差点
   直接删掉只存在于技能里的进展日志。
5. **同一批派活卡片长期存两代（S3–S7 与 W2-A…W3-C）**，说明派活剧本缺唯一落点；它的家是
   `reports/prompts/`，清单里只该有一行。

# `cleanup -l/--list` + 删私有 `--verbose` + cache 帮助面翻译

> 2026-09-22 ｜ 2 提交 `cd67788` `65b83ee`，worktree `.worktrees/cleanup-list-l`，分支 `feat/cleanup-list-versions`

**起因**：用户点名两处帮助面问题——`cleanup` 的「私有 `--verbose`」、`-a/--all` 与 `[APP]...` 描述不准确、要加 `-l`；`cache` 的位置参数 `[APP]...` 未翻译（`App name(s) whose caches are listed (default: all)`）。

**用户决策（2026-09-22）**：① `-l/--list` = **列出存在的版本**（不是替代 `-v`）；② 私有 `--verbose` 与它门控的「已清理干净」报告**彻底删除**（含 i18n 键）；③ 输出「参考 `list -V` 简化一下」；④ 裸 `cleanup -l`（无 app 无 `-a`）= 全部已装 app。

**改动**：① `src/cmd/cleanup.rs` 删掉命令私有的 `verbose: u8`（`-v` 从此回落全局 `clap_verbosity_flag`，`hok cleanup -v` 与 `hok -v cleanup` 等价、帮助文案变回共享的「增加日志详细程度」），`render_settled` 的 verbose 分支与 `cmd.cleanup_already_clean` 键一并删除，`reported` 只剩「确有版本被删」；② 新增 `-l/--list`：数据复用 `package::list::list_installed_versions`（与 `list --versions` 同源，杜绝第二套版本枚举），渲染是 `list --versions` 的简化版（名称|版本|状态三列，当前版本为首行带 app 名的加粗行、其余为暗色续行 + `旧版本`，无版本目录的 app 打 `-` + `无版本目录`）；只读 ⇒ 跳过 `-g` 的管理员门，`-k` 用 clap `conflicts_with` 拒绝组合；③ cache 帮助面三处未翻译一次修掉（顶层缺 `cli_help.cache.args.app`；`list.query`/`remove.query` 是字段改名后遗留的过期键 ⇒ 子命令位置参数一直显示英文）；④ `tests/cli_help_i18n.rs` 的检查扩到 `[ARG]...` 行（原先只扫 `-`/`<`，正是它让 cache 的英文位置参数在测试全绿下漂移）；⑤ `tests/exit_codes.rs` 补 3 条（裸 `-l` = 0、`-l ghost` = 0、`-l -k` = 1）。

**验证**：worktree `cargo test -p hok` 全绿（lib 49 → 含新增 2 条；`cli_help_i18n` 3、`exit_codes` 9、`i18n_keys` 3 等）；`cargo test -p libscoop` **760 passed / 2 failed**，两条 `permission::grant_users_write_inherit_*` 是沙箱 ACL 基线失败（`error 5`，与本次无关）；`cargo clippy --workspace --all-targets --exclude innospect --no-deps -- -D warnings` 干净；改动文件 `rustfmt --edition 2024 --config skip_children=true --check` 干净。隔离 `SCOOP`/`HOME` 根端到端：`cleanup -l demo` → `demo 2.0.0` + 暗色 `1.0.0 旧版本`（junction 夹具）、裸 `cleanup -l` 同时列出 demo 与 other、`cleanup -l ghost` 报 `'ghost' 未安装。` exit 0、`cleanup -l -k` clap 冲突 exit 1、`cleanup --help`/`cache --help`/`cache list -h`/`cache remove -h` 逐行复核；landed 到 `refactor/edition-2024`（`65b83ee4`，脚本漂移校验：2 提交 / 主题 / 6 文件集守恒 + 树逐字节相同，无 merge commit）。

**坑**：① `-l` 首版沿用破坏性路径的 `all = args.all || any('*')` ⇒ **裸 `cleanup -l` 静默无输出**（只读语义的「留空 = 全部」必须单独算：抽 `lists_every_app()` 并用 `Args::try_parse_from` 单测钉死）；② 新写的 en.yml 键 `app: App name(s) whose caches are listed (default: all)` 是**非法 YAML**（未加引号的值里含 `": "` 会被当嵌套映射），`hok-i18n` 的 build.rs 直接 panic、连编译都过不去 —— 值里带 `: ` 一律加引号；③ GPG 签名在 `workspace-write` 沙箱下起不来（`gpg-agent` 要往 Scoop 的 gpg home 写锁/socket，被拒），必须一次性 `danger-full-access` 起 agent，之后普通提交即可签名。

**追加（2026-09-23，用户实机反馈「为何报 `potplayer 260819 旧版本`」）**：用户本机 `hok cleanup -l` 里 `potplayer  260819  旧版本`。只读排查结论：该 app **缺 manifest/install.json**（`apps\potplayer\260819` 下一个 `.json` 都没有，而抽样 12 个其它 app 两者齐全），于是单一解析器 `resolve_current_version`（`package/install_state.rs:122`；分支 1 读 `current\manifest.json`、分支 2 退到 `install.json` 最新）**两条都失败 ⇒ 返回 None**，`-l` 就把唯一一行（junction 目标 260819）当「非当前版本」打出 `旧版本`，读起来像"这是个可清理的旧版本"。同一原因在别处一致：`hok list potplayer -V` 主行版本列为空 + `安装失败, 来源未知`；破坏性 `hok cleanup potplayer` 走 `confirm_installation_status` → 报 `'potplayer' 未正确安装。请重新安装或修复其 manifest。` 并**跳过**（不会删 260819，安全侧）。**用户拍板 B**：解析不出当前版本时不再打 `旧版本`，改打中性提示，**并要求 `list -V` 一并改**。实现分两步：① `2eba651` —— 抽纯函数 `version_note(index, is_current, has_current) -> VersionNote{None,Old,CurrentUnknown}`（新键 `cmd.cleanup_list_current_unknown` =「当前版本未知」/`current version unknown`），`-l` 的 block 首行报未知、其余行不打注记（没人是"已知的旧版本"，只读清单不该越权断言）；② `daa1002` —— 把该判定**上移到 `src/cmd/mod.rs`**（`VersionNote` + `version_note`，与 `status_info_word`/`InfoContext` 同一处：共享显示词的单入口），`list -V` 的 retained 行改调它，于是两个表不可能漂移；顺带**不再把这些目录算进页脚「保留了 N 个旧版本」**（`stats.retained` 只在 `has_current` 时累加）——否则新行刚说「当前版本未知」，下一行立刻又说「保留了 1 个旧版本」，且这类 app `cleanup` 本就跳过、根本不是可清理的旧版本。健康 app 的 `旧版本` 与计数完全不变（73 app / 6 旧版本实测一致）。

# hok 多子代理并行开发编排纪律

**何时加载**：准备把一批工作（计划里的 S/R 条目、审计清单）**分派给多个可续子代理并行做**，或作为**父会话**负责收口时。机制层（worktree/分支/合并脚本/沙箱坑）见 [[hok-worktree-parallel]]，通用并行纪律见全局 `worktree-parallel`。

## 0. 一句话
**并发不是免费的**：每条并行分支的收口成本 ≈ 一次 rebase + 一次门禁 + 可能的**手工重放**；先做重叠矩阵、封顶 2–3 条，比多开几条快得多。

## 1. 派活前：重叠矩阵（**必做，两步**）
1. **文件重叠**：把每条子任务的改动面列出来，标出热点文件。hok 的**必然冲突热点**：
   `locales/en.yml`、`locales/zh.yml`、`README.md`、`README-zh.md`、`src/cmd/mod.rs`、`tests/exit_codes.rs`。
   ⇒ **热点文件同一时间只派一条会话**，其余串行或明确预告冲突并接受手工解。
2. **语义重叠**（更容易漏）：同一个**共享谓词 / 单入口 / 枚举**是否被两条同时改？
   实例：S10 的 D1 与 S11 的 Q4(a) 都在改 `internal::string::matches_any_glob`（一条加了大小写不敏感、另一条加"忽略 `.json` 后缀"）——只看文件看不出，结果白白多花一次冲突解决。
   ⇒ 先 grep 目标符号的**现有引用点**，再决定归属；**共享符号只派一条**。

## 2. Prompt 契约（每条子代理 prompt 必须含）
1. **自包含**：子代理看不到父会话（除非 `subagent_fork`），范围/决策门/验收/提交拆分必须写全。
2. **硬性禁令清单**：不写**汇总型热点文件**（清单与"只在主树改"的规则见 [[hok-worktree-parallel]]）；不碰别的会话 worktree；**不合主线**（只报"可合并 tip"）；**不派生下一级子代理**（保持血统扁平、可控）。
3. **已知环境坑**：至少含 `hok-worktree-parallel` 的沙箱四条（`rebase --continue` 不通 / `-F` 写提交信息 / 禁 `reset --hard` / `-VerifiedRef` 语义）。
4. **主线快照 + 复查点**：告诉它"开工时主线 tip = X，若你的活跨多块，**每个块边界重看一次主线**是否有重叠工作落地"。
   实例：S9 三块做完时，D4 已落地并把 S9-1 的一半做掉了 ⇒ 只能重放调和。
5. **要求"证据命令"而不只是结论**：让它报出可复跑的命令与前后对照（这样父会话能廉价复核）。
6. **允许并鼓励用证据反驳父会话**：父会话只会给"推荐"，不是事实。实例：我给 D4 列的"+cookies"经查证是**不存在**的需求（官方两个调用点都传 `$null`），子代理用证据顶回来才对。

## 3. 决策门（`investigate-first` 的落地形态）
- 子代理**先出调研报告**（期望 vs 实际、证据、候选方案含"不做"、代价、影响面），**然后停下等用户回答**，**确认前禁止改代码**。
- 用户在**子代理自己的会话**里回答（GUI：会话头的 `/` 血脉目录进入；`@` 引用不能用来对话；**父会话必须活着**，否则子代理输入框变只读）。
- 用户在动代码前否决最便宜。实例：`Bearer` 而非官方 `token`、多 bucket C1 暂缓、D4b 分两组——都在实现前拍板。

## 4. 并发与批次
- **上限 2–3 条**在飞；超过就要预期"父会话手工重放"。
- 批次内部**互不重叠**优先（实例：Wave 1 = `checkver` 挂起 + 缺环境变量 panic，两条文件零交集）。
- 设计题（如"解析失败该报错/警告/计数"）**单开**，不要和机械修复混批。

## 5. 证据纪律（本轮最值钱的部分）
| 规则 | 理由/实例 |
|---|---|
| **实测 > 静态读码** | 审计说"hok 默认复用缓存"，换服务端内容 + 数请求后证明 hok 默认**每次重下**；真缺陷是缓存键不含版本 |
| **优先修"失败静默"** | 清单解析失败被 `query.rs` 的 `filter_map` 吞成"找不到软件包"，让 220 个真实包的 P0 无法定位（现状与行号见 [[scoop-gap-audit]]） |
| **量化影响面再决定做不做** | 用真实数据（本机 4 bucket / 21797 manifest）把"审计说偏离"变成"1160/3849 受影响"，顺带挖出 P0 |
| **独立复现是强信号** | `hok checkver` 挂起被两条会话各自独立发现 ⇒ 值得立项 |
| **先重跑再下结论** | "偶发红"先怀疑测试自身：进程级 once 闩锁 + 并行测试就会假 flaky（重跑即过），闩锁要挂在会话而非进程 static（教训见 [[hok-audit-fix-history]]） |
| **推翻旧文档 = 固化更正** | 更正旧结论（checkhashes 缓存、`mode: github`、`hashExtraction.mode`"8 枚举完全一致"）时必须**写回权威文档/状态表 + 一条 devlog**，只在对话里说一句等于没更正 |

## 6. 收口：落地检查单（父会话每次 ff 前 30 秒）
1. 分支引用是否指向子代理**报的** tip？（`git rev-parse <branch>`）——子代理手工重放后常把 tip 留在 **detached HEAD** 上、分支引用还停在旧位置。
2. worktree 是否**挂在分支上**（非 detached）？`git rev-parse --abbrev-ref HEAD` 应为分支名；否则脚本报 `ERR the worktree is on a detached HEAD`。
3. `merge-base --is-ancestor <mainline> <branch>` = true？
4. 主树里**未提交的跟踪文件**改动是否会被这次 ff 覆盖？（`git status --short` 看 ` M` 项；与分支改动集求交集）会就先 `git stash push -m "<会话>-merge-leftovers" -- <files>`，ff 后 `pop` 复原。
5. ff 后：**`git diff --cached --name-only` 必须为空**（收口脚本失败时会把无关文档误暂存进索引；发现即 `git reset` 复原）。
6. 落地后**在新树上重跑门禁**（若树与受测树逐字节相同可省，脚本会给出结论）。

## 7. 文档收尾与交接
- **每个落地会话的固定回填**：活动计划自己那行 + 审计报告对应条 + **一条 devlog**（触发与格式见 [`docs/AGENTS.md` R7](../docs/AGENTS.md)）；**汇总型热点文件只在主树改**（清单见 [[hok-worktree-parallel]]；子代理写得也没用，且并行会话必撞）。
- **"有意偏离"必须逐条登记**（含用户拍板的决定，如 `Bearer`、`-d` 只对写盘强制、`formatjson` 逐文件输出）——否则下次没人分得清"决定"与"疏忽"。
- **换对话前先写交接**：新会话**看不到**本对话，口头交接=没交接。做法：在计划文档末尾加一节（如 §8）写清**起点 tip、余项清单与建议、会话切分、可复制的开场 prompt、必读注意事项**，再让用户新开对话。

## 8. 一次真实并行的代价（量级参照）
8 条子代理并行 → 主线**线性落地、零 merge commit**；代价：2 次真冲突、1 次语义门、1 次手工重放（沙箱无编辑器）、1 次索引污染。
结论：**并发 2–3 条 + 先做重叠矩阵**，比多开几条快得多（当时的会话编号与提交数属记录，已归 devlog）。
